Supporting Paragraphs
---------------------

Shared memory and worker processes. The vectorization layer (vector.py:300-309)
allocates one flat RawArray per buffer type — observations, actions, rewards,
terminals, etc. — on the CPU heap. These arrays are laid out as
[num_workers × agents_per_worker × ...] and are mapped as numpy ndarray views
in both the main process and in every worker process, so there is no
serialisation or copying between processes. One worker process is spawned per
physical CPU core (vector.py:262), and each worker owns a contiguous row of the
shared memory corresponding to its envs_per_worker environments. The C
environment's c_step() function receives raw pointers into this shared memory
(set up via the C binding layer) and writes observations, rewards, and terminals
directly in-place, never allocating new memory.

The semaphore loop. Worker and main process synchronise through a semaphores
RawArray (vector.py:195-224). After c_step() completes, the worker sets
semaphores[worker_idx] = MAIN. The main process polls these semaphores in
recv() (vector.py:356-445) and waits until workers_per_batch workers have
raised their flags. Because both processes share the same memory, recv() returns
zero-copy numpy views directly into the shared observation rows — no data is
moved across a pipe. The main process then writes the chosen actions back into
the shared actions buffer and sets semaphores[w] = STEP, releasing the worker
to call c_step() again while the main process begins the policy forward pass.

The trajectory buffer. The main process maintains a separate set of GPU tensors
called the trajectory buffer (pufferl.py:95-110), shaped (segments, horizon, ...)
where segments = batch_size / bptt_horizon. With default settings
batch_size = total_agents × bptt_horizon, so segments = total_agents. This
buffer is what accumulates the full rollout before training. Two index arrays
manage the fill process: ep_indices[env_id] records which segment row a given
agent-batch currently writes into, and ep_lengths[env_id] records how many
timesteps have been written into that row so far. At each recv/send cycle the
main process copies the current observations, computed actions, log-probabilities,
critic values, rewards, and terminals into column l = ep_lengths of the assigned
rows (pufferl.py:284-296). When a row reaches horizon timesteps it is marked
full and, if more segments remain to fill, the agent-batch is assigned a new row.
The collect loop runs until full_rows >= segments (pufferl.py:244).

Moving data to the GPU. The shared memory observations arrive in the main process
as a pageable CPU numpy array. The main process converts them with
torch.as_tensor() (zero-copy, still on CPU) and then calls .to(device) to move
them to the GPU (pufferl.py:255-256). This triggers a CUDA host-to-device
transfer — because the memory is pageable (not pinned), the CUDA driver
internally stages it through a temporary pinned buffer before DMA. The
cpu_offload option (pufferl.py:287-290) avoids this by keeping observations in
CPU pinned memory throughout the trajectory buffer and only transferring the
minibatch slice at train time, which can be worthwhile when the observation
tensor is large.

The train phase. Once the trajectory buffer is full, training begins
(pufferl.py:332-476). The unified GAE + V-Trace advantage kernel runs on the
GPU over the full (segments, horizon) buffer, producing an advantage estimate
for every timestep. Priority sampling then draws minibatch_segments segment
indices with replacement, weighted by total advantage magnitude per segment.
The selected rows are gathered into a minibatch, reshaped from
(minibatch_segments, horizon, obs_shape) to (minibatch_size, obs_shape), and
fed through a full policy forward pass to obtain new log-probabilities and
values. The PPO clipped surrogate loss, clipped value loss, and entropy bonus
are combined, backpropagated, and the gradient step is taken, with gradient
clipping applied before the optimiser step. This entire train phase operates
exclusively on GPU tensors; no data moves back to CPU until the next collect
phase begins.
